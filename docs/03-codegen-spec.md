# 03 — Code generation specification

`functions.toml` is the single source of truth. Five artifacts are generated from it;
none may be hand-edited.

```
docs/functions.toml
   │
   └─► tools/regen.py
          ├─► accudist/_ufuncs.c        ufunc registration + nogil inner loops
          ├─► accudist/_api.py          public wrappers: defaults, kwargs, dispatch
          ├─► accudist/_generated.pyi   type stubs
          ├─► accudist/rmath.py         raw 1:1 C-signature escape hatch
          └─► tests/test_manifest.py    one parametrized test per function
```

`tools/regen.py --check` regenerates into a temp dir and diffs; CI fails if anything is
stale. Every generated file starts with `# GENERATED by tools/regen.py — do not edit`.

## Schema

### `[meta]`

| key | type | meaning |
|---|---|---|
| `schema_version` | int | bump on any breaking schema change |
| `r_version` | str | R release the inventory was verified against |
| `source_c_header` | str | path to the vendored `Rmath.h` |

### `[[func]]` — generates a ufunc + wrapper

| key | type | required | meaning |
|---|---|---|---|
| `name` | str | yes | public Python name |
| `kind` | str | yes | `d` \| `p` \| `q` \| `r` \| `special` \| `util` |
| `family` | str | dist only | e.g. `pois`, groups d/p/q/r |
| `r_page` | str | dist only | R help page, for docstring links |
| `milestone` | str | yes | `M2`, `M3`, … — controls what you build when |
| `params` | array of tables | yes | public parameters, **in public order** |
| `flags` | array of str | yes | `["lower_tail","log"]`, `["log"]`, or `[]` |
| `dispatch` | str | no | `ncp` \| `prob_or_mu` |
| `alias` | str | no | `rate_scale` |
| `cache` | str | no | `wilcox` \| `signrank` — needs the cache lock |
| `c_transform` | table | no | Python expressions applied before the C call |
| `summary` | str | no | one-line docstring |
| `r_equivalent` | str | no | the R spelling, for the docs mapping table |

`params` entries: `{ py = "name" }`, or `{ py = "name", default = <value> }`.
A missing `default` means the argument is required.

### `[func.call]`, `[func.call_ncp]`, `[func.call_mu]`

| key | meaning |
|---|---|
| `c_symbol` | the symbol in `Rmath.h` to call |
| `c_args` | **the order the C symbol expects.** Not necessarily the public order. |
| `composed` | a Python expression used *instead of* a C call (see below) |

> **`c_args` is the whole point of this schema.** It is the one place where the public
> argument order and the C argument order are reconciled, and it is checked by tests.
> Never "tidy" it to match `params`.

### `[[bespoke]]`, `[[rng_primitive]]`, `[[excluded]]`

`bespoke` entries are **not** generated — they get hand-written wrappers in
`accudist/_bespoke.py` because they are not scalar→scalar (out-params, array
arguments, or array returns). `excluded` entries are symbols in `Rmath.h` that are
deliberately absent from the public API, each with a `reason`.

## Generating `_ufuncs.c`

One ufunc per distinct `c_symbol`. Signature: all `c_args` as `double` inputs, then one
`long` input per entry in `flags`, then one `double` output.

```
ppois  → types: d d l l -> d        (q, lambda, lower_tail, log)
dpois  → types: d d l   -> d        (x, lambda, log)
rpois  → types: d       -> d        (lambda)
beta   → types: d d     -> d        (a, b)
```

Flags are ufunc *inputs*, not specializations. There is no benefit to generating four
variants: the C function takes the flags as arguments regardless, so a specialized
variant would have nothing to specialize away.

Inner loop template:

```c
static void ppois_loop(char **args, npy_intp const *dims,
                       npy_intp const *steps, void *data)
{
    npy_intp n = dims[0];
    /* GIL is already released by the ufunc machinery for this loop */
    for (npy_intp i = 0; i < n; i++) {
        double q   = *(double *)(args[0] + i * steps[0]);
        double lam = *(double *)(args[1] + i * steps[1]);
        long   lt  = *(long   *)(args[2] + i * steps[2]);
        long   lg  = *(long   *)(args[3] + i * steps[3]);
        *(double *)(args[4] + i * steps[4]) = ppois(q, lam, (int)lt, (int)lg);
    }
}
```

Rules:

- The loop body is **only** the C call. No validation, no branching on values, no
  Python API calls — the GIL is not held.
- Error signalling is via the thread-local word set inside nmath by the shim. The loop
  never inspects it.
- Functions with `cache = "wilcox"` or `"signrank"` must **not** run GIL-free
  unguarded; the wrapper takes the cache lock first. See [05-errors.md](05-errors.md).

## Generating `_api.py`

```python
def ppois(q, lambda_, lower_tail=True, log=False, out=None):
    """Poisson distribution function.  R: ppois(q, lambda, lower.tail, log.p)"""
    with _errstate.capture("ppois") as _c:
        r = _ufuncs.ppois(q, lambda_, int(lower_tail), int(log), out=out)
    _c.check()
    return r
```

For `dispatch = "ncp"`:

```python
def pchisq(q, df, ncp=None, lower_tail=True, log=False, out=None):
    with _errstate.capture("pchisq") as _c:
        if ncp is None:
            r = _ufuncs.pchisq(q, df, int(lower_tail), int(log), out=out)
        else:
            r = _ufuncs.pnchisq(q, df, ncp, int(lower_tail), int(log), out=out)
    _c.check()
    return r
```

For `dispatch = "prob_or_mu"` and `alias = "rate_scale"`, the generator emits the
argument-resolution preamble described in
[04-api-reference.md](04-api-reference.md#parameterisation-dispatch).

For `composed` entries (`rbeta`/`rf`/`rt` with `ncp`), the generator emits the Python
expression verbatim — these have no C symbol and **must** reproduce R's own R-level
composition exactly, including the order of RNG draws, or the results will differ.

## Generating `rmath.py`

A flat, undecorated 1:1 mapping to `Rmath.h`, positional only, no defaults, no
dispatch, `int` flags:

```python
pnchisq = _ufuncs.pnchisq     # pnchisq(x, df, ncp, lower_tail, log_p)
```

This is where `dbinom_raw` and `dpois_raw` live. Nothing in `accudist/` may import it.

## Adding a function

1. Add the `[[func]]` entry to `docs/functions.toml` **in this repo**, via
   `tools/gen_functions_toml.py` — not by hand-editing the TOML.
2. Copy the regenerated `functions.toml` into the implementation repo.
3. `python tools/regen.py`
4. `Rscript tools/gen_reference.R --only <name>`
5. `pytest -q -k <name>`

If the function is in `[[excluded]]`, write an ADR before doing any of this.
